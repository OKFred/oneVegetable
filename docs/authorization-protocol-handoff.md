# 授权协议接续保存

## TOP / IOP 前置检查

| 子能力               | TOP                                   | IOP                          | 风险与运行边界                                             |
| -------------------- | ------------------------------------- | ---------------------------- | ---------------------------------------------------------- |
| 授权工具保存到工作台 | 现有 `apply-to-workbench`，仅更新 TOP | 同一现有操作，仅更新 IOP     | 本机加密存储，不调用 Alibaba；保留另一份授权及既有默认协议 |
| 继续另一协议         | 保存当前 TOP 后切到 IOP               | 保存当前 IOP 后切到 TOP      | 不自动发现应用、发起 OAuth 或重放任务                      |
| 保存所需主机权限     | `eco.taobao.com`                      | `openapi-api.alibaba.com`    | 使用现有精确业务 Origin；不增加永久权限                    |
| 真实只读连接验收     | `alibaba.icbu.product.list`           | `/alibaba/icbu/product/list` | 现有签名与凭据选路不变，无业务写入                         |

## 行为

- “授权已就绪”仍表示授权工具已安全保存，不能单凭此状态宣称工作台已启用。
- 点击“保存并继续授权另一协议”时，先等待当前协议的工作台保存回执。回执必须明确为 `applied: true`，且协议与当前操作一致。
- 保存期间禁用重复操作；成功后才清理临时输入并切换页面协议，显示保存成功通知。
- 权限被拒绝、运行时保存失败或回执不完整时，保留当前页面并显示原因。可选择“返回重试”或“仍然切换”；后者不声称已保存，也不删除工具中的授权。
- 首次使用以第一份成功保存的授权为默认；保存第二份不会改变既有默认协议。
- “继续另一协议”仅在另一份尚未保存到工作台时展示。只在授权工具就绪的文件不计为已配置；另一份已经保存时，当前页只需完成“保存并进入工作台”。
- 复用现有 `protection-status.pool` 的协议布尔状态，不新增 Alibaba 请求或返回敏感凭据。工作台授权保存或清除后，通过本机存储通知同步按钮状态。
- 已完成在线授权后遗留的隐藏表单字段不再触发无意义的放弃输入确认。真正重新编辑的输入仍保留确认。

## 远程验证

- 正式 MV3 自动回归覆盖 IOP 在线授权回调 → 继续 TOP → 导入文件 → 最终保存；同时覆盖相反顺序、刷新保留、权限拒绝、保存失败、不完整回执及重复点击。
- 隔离的真实验收从已获得的真实 IOP 授权包开始，只存入工具、不预先应用到工作台，再按上述交互完成两份授权保存；刷新后保留两份授权和 IOP 默认。
- TOP 和 IOP 分别通过真实商品列表只读连接测试。不重新签发 OAuth，不改动用户日常 Profile，不刷新 Token，不修改商品。
- 原生权限同意在自动验收副本中预先授予，不能据此宣称重新验收了 Chrome 权限弹窗或人工 Alibaba 授权协议确认。
- 脱敏回执位于远程忽略目录 `artifacts/authorization-switch/real-receipt.json`；密钥、Token、完整响应不入报告或 Git。

本轮仅提交并推送修复，不自动合并主线、部署网站或发布商店。
