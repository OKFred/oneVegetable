- 使用用户提供的 RustFS S3 配置，私有 bucket，path-style；凭据仅保存到本地加密配置。

## 映射方式

- 设置中的根前缀是 S3 访问边界。导出弹窗可填写其下的相对前缀，每次另建时间+随机标识批次，避免覆盖。
- 导出可平铺到一个 `assets` 目录，或在其下保留图库分组层级；目录名按 URL 编码，清单保存原始分组路径。未知分组使用 ID，未分组使用 `Ungrouped`。
- 真实 UI 导出后，S3 扫描回读到 `mapping-check/20260908T034136Z-07b3c926/assets/Test%20Upload/33401160276-Hf3dc2ce540b548dea1950dbdbb424375m-55e5de235bde.png`，确认自定义前缀及分组层级生效。
- 导入可按设置中的多个来源前缀/Glob 规则映射到不同已存在分组，也可把所有扫描到的图片导入当前选中分组。
- 改变映射方式后原扫描计划失效，必须重新扫描。“自动创建缺失的图库分组”默认勾选，先校验全部路径不超过三级，再按父到子调用分组新增接口；取消勾选时，目标缺失会在首张上传前停止。无权限或创建失败不会降级到其他目录。
- 此功能是用户主动执行的导入导出，不是后台持续同步；不删除或覆盖旧素材。当前扫描仍有 500 对象上限。

## 失败恢复与三级路径回归

以下通过受控单元/组件测试验证，不人为中断真实上传，也不增加线上素材：

- 已存在两级目录时，只向真实父分组 ID 创建第三级；超过三级在任何新增或上传前拒绝。
- 创建分组的返回结果使用请求中的真实父 ID，而非返回的层级编号。
- 上传响应缺少 fileId 或素材 URL 时不认定成功。
- 部分图片成功后，后续下载失败仍保留成功回执；可继续未出网的条目，不重发成功项。
- 上传未取得确认时，将其从本弹窗待执行队列移除；相同对象 ETag、路径和目标分组的重新扫描不会重新加入。界面提示先在平台核对。
- 新建分组未取得确认时暂停本次执行，避免用户直接点击重试导致重复分组；核对平台后重新打开弹窗。
- 同名跳过有独立回执；回执随界面语言切换，部分成功时也会刷新图库数据。
- 上传或扫描中禁止切换存储来源，不使用旧扫描计划执行导入。

这是当前弹窗会话内的重复提交保护，不是持久化幂等协议；关闭或刷新页面会清空会话记录，平台结果不明时必须先人工核对再重开。已完成真实成功场景的记录见上文，不能将模拟超时测试表述为平台故障验收。

S3 测试对象保留在 smoke 前缀；未自动删除线上图库素材。
