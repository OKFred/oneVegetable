# 图库 S3 本地真实验证（2026-09-08）

## 环境与边界

- Windows Node BFF + Web，独立 SQLite 验证库；Alibaba 使用真实凭据，不回退 Mock。
- 使用用户提供的 RustFS S3 配置，私有 bucket，path-style；凭据仅保存到本地加密配置。
- S3 测试对象使用独立 smoke 前缀，不覆盖已有业务对象。
- 首轮执行一次图库上传；后续分别受控复核相同图片复用和不同图片新增。未执行商品、订单或 RFQ 写操作。
- 本记录不代表 Worker 部署、Supabase S3 或插件 S3 已完成真实验收。

## 已验证

1. S3 客户端上传、列举、下载成功，下载内容 SHA-256 与原文件一致。
2. 设置页可加密保存 S3 配置和本机导入规则。
3. 图库 UI 导出一张真实素材到 S3，随后扫描发现一张图片及导入计划；JSON 清单不作为图片导入。
4. 规则将图片映射到 `Test Upload`。二次确认后 BFF 执行一次 `uploadPhoto`，审计结果为 `OPERATION_SUCCEEDED`，requestId 为 `873d807e-30e1-474c-8d24-3be380810fe2`。
5. 修正 S3 模式的弹窗说明与导出确认文案，不再错误提示生成 ZIP。

## 后续复核：原因已确认

对同一原图更换文件名、传入目标分组再次上传后，平台仍返回原 fileId `33388728548`（平台 request_id `16l5d349dcql8`），原素材没有移动到目标分组。该样本证实平台复用了已有素材，不是前端缓存。

使用项目现有图标作为不同内容上传，得到新 fileId `33401160276`，目标 `Test Upload` 分组立即回读成功，Web 列表也显示此图。测试图片留在该组，未自动删除。

UI 现在保留每张素材 fileId 和回读结果。上传已成功但目标分组前 100 项找不到时，明确显示尚未确认，不自动移动、不重复上传；回读失败也不会重新上传。更深分页的缺失不判定为平台失败。

## 映射方式

- 设置中的根前缀是 S3 访问边界。导出弹窗可填写其下的相对前缀，每次另建时间+随机标识批次，避免覆盖。
- 导出可平铺到一个 `assets` 目录，或在其下保留图库分组层级；目录名按 URL 编码，清单保存原始分组路径。未知分组使用 ID，未分组使用 `Ungrouped`。
- 真实 UI 导出后，S3 扫描回读到 `mapping-check/20260908T034136Z-07b3c926/assets/Test%20Upload/33401160276-Hf3dc2ce540b548dea1950dbdbb424375m-55e5de235bde.png`，确认自定义前缀及分组层级生效。
- 导入可按设置中的多个来源前缀/Glob 规则映射到不同已存在分组，也可把所有扫描到的图片导入当前选中分组。
- 改变映射方式后原扫描计划失效，必须重新扫描。“自动创建缺失的图库分组”默认勾选，先校验全部路径不超过三级，再按父到子调用分组新增接口；取消勾选时，目标缺失会在首张上传前停止。无权限或创建失败不会降级到其他目录。
- 此功能是用户主动执行的导入导出，不是后台持续同步；不删除或覆盖旧素材。当前扫描仍有 500 对象上限。
