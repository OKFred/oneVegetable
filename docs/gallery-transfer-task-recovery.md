# 2.6.0 图库传输任务中心

状态：本地候选验收通过。分支 `codex/gallery-transfer-task-recovery` 从包含 2.5.0 主线的 staging 创建，尚未合入主线。

## 固定边界

- ZIP/S3 导入导出共享应用级执行器；关闭弹窗与切页继续，刷新或关闭标签页停止调度，恢复需用户确认。
- IndexedDB 只保存版本化任务元数据；发送前落盘，未知结果不自动重发。成功回执与目标位置核对分开。
- Web Locks 同 Origin 单任务执行；不支持锁时拒绝执行，不自动接管其他窗口。
- ZIP 恢复重新选择原包；S3 保存确定目标 key，重试前核对源指纹与目标内容。密钥、图片和完整响应不存任务记录。
- 账号/配置上下文由后台核对，不替代权限、CSRF 或 mutation flag。
- 不新增永久扩展权限，不自动部署 Worker、发布商品或提交商店。

## 使用方式与保留规则

- 图库的“导入”“导出”先预览并冻结文件、路径、冲突策略与自动创建选项，确认后进入“传输记录”。关闭抽屉不停止任务；页面底部保留活动进度入口。
- 暂停/取消只停止后续调度，等待已经发出的请求回写。刷新或退出浏览器后，重新打开工作台只恢复记录，继续执行必须再次确认。
- ZIP 恢复需重新选择 SHA-256 相同的原包。S3 恢复核对 key、大小、ETag；写入结果不明时先 GET 比对 SHA-256，不能直接重传。
- 图库返回 fileId 后按目标分组完整分页核对；同名不算成功证据。遇到平台复用其他目录的旧图片时，保留“成功待核对”，不移动、不重传。
- IndexedDB 最多保存 100 个任务、每个最多 500 张图片；完成/取消记录保存 30 天，未解决记录不自动删除。任务中不保存图片字节、Base64 或凭据。用户主动清理记录不会删除远端文件。
- 正常 Token 刷新不改变任务账号上下文；更换工作台身份、Alibaba 凭据或 S3 配置后，旧任务不能继续写入。ZIP 任务同样保留创建时的完整配置上下文。
- 私网 RustFS 只在明确勾选可信局域网 HTTP、使用 RFC1918 IPv4 和 Path-style 时允许。Node 还必须设置 `ONE_VEGETABLE_ALLOW_LOCAL_S3_HTTP=1`；Worker、staging、production 不开放此例外。不要把此配置用于公共网络。

## 2026-09-10 真实验收

用户授权在 `192.168.1.4:9000` 创建独立 RustFS 测试桶，并使用已有 OSS `dev` 桶下的新测试前缀。密钥与浏览器 Profile 只在忽略的 `artifacts/gallery-transfer-2.6/`，不进入仓库。

| 路径                            | 实际结果                                                                                                       |
| ------------------------------- | -------------------------------------------------------------------------------------------------------------- |
| RustFS → Web/Node BFF → Alibaba | 新建隔离图库组，2 张独立测试 PNG 上传后按 fileId 在目标组确认                                                  |
| Web S3 导出                     | 第一张真实 PUT 成功后暂停；切页、刷新不自动继续，手工恢复只上传第二张和最后的清单；GET 哈希一致                |
| Web ZIP 导出/导入               | ZIP 含 2 张图片及清单；导入首张后暂停、刷新，错误原包被拒绝，选对原包后仅上传剩余项                            |
| 正式构建插件 → RustFS           | 用户原生授权后，PUT/LIST/GET 哈希一致；service worker 重启后只读回验通过，没有重发此前 PUT                     |
| 插件独立任务                    | S3 导入取消自动建组后正常进入已有测试组；ZIP 导出、ZIP 导入、S3 导出均完成；暂停、刷新、手工恢复通过，无需 BFF |
| OSS → Alibaba 去重分支          | 上传返回原 fileId，但图片仍在先前的测试组。新目标组未确认，任务停为需处理，第二张保持待处理，未自动重传或移动  |

最后一行是安全保护验收，不是“OSS 新组导入全部成功”。额外只读查询确认该 fileId 确实存在于原测试组。平台没有被要求移动或删除图片。保留该待核对任务与空测试组，以便后续人工处理。

回执（本机忽略文件）分别为 `local/web-real-report.json`、`local/recovery-real-report.json`、`local/zip-recovery-report.json`、`extension-rustfs/restart-report.json`、`extension-rustfs/task-report.json`、`extension-rustfs/task-recovery-report.json`、`oss/unconfirmed-readback.json`。所有路径相对于上述 artifacts 目录。

测试脚本的首次插件重启阶段未通过，另一次暂停测试因 Playwright 字符串谓词触犯 MV3 CSP 在写入前停止；修正测试驱动后沿用原 Profile/待处理任务完成验收，没有放宽 CSP 或预授权修改 Manifest。不要在真实浏览器运行期间重建其加载目录。

## 自动化边界

已覆盖发送前落盘、存储失败、上下文变化、未知 PUT 的先核对、超过 100 条的图库分页、ZIP 原包校验、Web Locks 双标签互斥、清理、双语及暗色模式。平台超时/权限失效等分支使用可重复 FakeTransport/隔离 E2E，不宣称人为触发过全部真实平台故障。

真实脚本均显式 opt-in，不进入 CI；检查已有回执后再运行，不能以重跑整个脚本代替任务恢复。没有修改商品，没有删除远端素材，没有自动部署 Worker 或提交商店。
