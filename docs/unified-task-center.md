# 统一任务入口与失败处理

工作台增加 `#/tasks`（任务中心），复用已有任务存储和执行器，不增加新的业务写能力、后台自动恢复或任务数据库。

## 记录来源

| 来源                         | 读取范围                                                        | 后续入口                                 |
| ---------------------------- | --------------------------------------------------------------- | ---------------------------------------- |
| 商品发布、草稿、更新、上下架 | 当前工作台身份可见回执，每次 100 条，可手工加载更多             | 精确任务 ID 的只读历史页面               |
| 批量发品                     | 仅将 `mutationJobId` 能匹配已加载商品回执的本地队列项关联到记录 | 未匹配队列仅提示数量，保留原批量队列入口 |
| 图片 ZIP/S3 导入导出         | 既有 IndexedDB 任务和逐文件回执                                 | 原传输记录抽屉                           |
| 视频上传                     | 当前身份最近最多 100 条既有任务                                 | 原视频上传弹窗，按任务 ID 定位           |
| 视频关联                     | 当前运行模式、身份和凭据上下文中每个商品的最新本地回执          | 只读关联回执和人工核对                   |

任务中心不是无限历史归档；筛选仅作用于已加载记录。原任务的保存期限、配额、隔离和清理规则保持不变。页面只读取记录，不启动、重试、恢复、核对或清理远端操作。

## 状态与操作

- 区分待开始、执行中、已提交/待核对、已确认、需处理/结果不明、明确失败、已取消。
- 平台受理不等于回读确认；取消也不会抹去结果不明的写入。
- 默认需要处理的任务优先，支持业务、状态、更新日期和名称/ID/requestId 搜索。
- 详情显示原任务状态、requestId、traceId、实际记录的最后核对时间、文件或分片步骤。没有核对时间时显示“原任务未记录”，不以刷新时间代替。
- 根据稳定错误码引导重新登录、解锁、检查权限/配置、重新选择原文件或先核对结果。实际执行继续由原流程负责确认和授权，不提供通用“强制重试”。
- 列显隐、排序和本页选择复用现有 DataTable；中英文、暗色及窄屏使用共享组件。

## 账号与隐私边界

读取前后分别核对不透明上下文，身份或配置变化时丢弃迟到结果、清除旧详情。来源读取失败彼此隔离，不用 Mock 补齐真实失败。

旧商品任务没有保存 Alibaba 账号指纹，因此只能认为它是当前工作台身份有权查看的历史，不能证明属于当前 Alibaba 凭据。任务中心始终提示这一限制，跳转 `#/products/tasks/<id>/history`：只读取任务记录，不查询平台状态、不恢复任务、不自动修复本地队列。原商品任务页面保留其已有操作逻辑。

旧批量队列没有 owner，未匹配项不展示商品内容、不自动迁移或归属到当前账号。图片/视频任务的身份不符则隐藏；凭据或存储变化则仅显示历史，禁止直接恢复。

展示模型不携带完整 Schema/XML、文件 Base64、S3 key、预签名 URL、原始响应或自由文本平台错误。可复制 requestId；具体诊断继续在原业务流程查看。

## 验证

模拟数据统一在 `mock/data/task-center`。自动测试覆盖保守状态映射、账号边界、来源隔离、分页、损坏记录、无自动写入、迟到回执、只读任务深链接及中英文筛选。浏览器回归使用隔离 Web/正式 MV3 环境，阻断外部请求，验证查看结果不明记录后其状态仍为未知。

本轮不进行 Alibaba mutation，不部署 Worker，不变更版本号或覆盖已有商店 ZIP；正式发布单独确认。
